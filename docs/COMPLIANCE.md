# سیاست داده و یکپارچگی

این سند ادعاهای محصول را با وضعیت فعلی مخزن هم‌راستا می‌کند.

## رفتار محصول

- صفحه‌ها و APIهای جست‌وجو فقط offerهایی را می‌پذیرند که از منبع واقعی/ snapshot محلی آمده‌اند؛ جدول برنامهٔ آزمایشی، فایل‌های تست و آرشیو مستندات نباید وارد نتایج محصول شوند.
- نبود snapshot واقعی به معنی نتیجهٔ خالی است؛ برنامه قیمت یا ظرفیت نمونه، نرخ زندهٔ ساختگی یا تخمین قابل‌خرید نشان نمی‌دهد.
- `/search`، `/flight`، `/compare` و API جست‌وجو با همان لایهٔ سرویس جست‌وجو کار می‌کنند. APIهای retired/live قدیمی نیز دادهٔ نمونه برنمی‌گردانند.
- بازکردن صفحهٔ وب یا API وضعیت crawler، crawler را راه نمی‌اندازد و به فروشنده درخواست نمی‌فرستد.
- snapshot فقط اطلاعات ثبت‌شده در زمان جمع‌آوری است؛ قیمت و موجودی زمان خرید را تضمین نمی‌کند.

## قواعد نمایش و محاسبه

1. مقدار نامعلوم نامعلوم می‌ماند؛ بار، استرداد، ظرفیت، شمارهٔ پرواز یا قیمتِ غایب حدس زده نمی‌شود.
2. نرخ فقط با ارز و مبلغ نرمال‌شده و قواعد صریح منبع مقایسه می‌شود. تبدیل نامطمئن یا ارز نامقایسه‌پذیر، نرخ را واجد مقایسه نمی‌کند.
3. قیمت کارت، نوار تاریخ و API از یک قاعدهٔ انتخاب نرخ استفاده می‌کنند.
4. دادهٔ آزمایشی در تست‌ها می‌تواند برای پوشش رفتار کامپوننت استفاده شود، اما فقط در محیط تست و پشت mock؛ هیچ تستی مجاز نیست آن را به مسیر واقعی کاربر تزریق کند.
5. آرشیوهای صرفاً مستنداتی، اگر افزوده شوند، باید جدا از مسیر جست‌وجو بمانند و پیش از انتشار از اطلاعات محرمانه پاک‌سازی شوند.

## حریم و امنیت

- `.env` و فایل‌های محلی پیکربندی، secretها، headerها، cookieها و tokenها نباید commit شوند.
- `data/crawl/` منبع دادهٔ عملیاتی محلی است و نباید commit شود.
- logها و گزارش خطا نباید secret یا URL دارای credential را ثبت کنند.
- محدودکنندهٔ نرخ در هر process حافظهٔ محدود دارد؛ پشت proxy فقط با پیکربندی آگاهانهٔ `TRUST_PROXY=1` به headerهای IP اعتماد می‌کند.

## راستی‌آزمایی

تست‌های repository قراردادهای تاریخ، نرمال‌سازی، dedupe، رتبه‌بندی، فیلتر دادهٔ واقعی، مسیرهای API، محتوای README و رابط را بررسی می‌کنند. پوشش واقعی Safarmarket، دسترسی شبکه/مجوز منبع، پیکربندی عملیاتی crawler و موجودبودن snapshot در یک نصب مشخص، از این تست‌های واحد اثبات نمی‌شوند.

# ترب‌بلیت (Torob Tickets)

یک نمونهٔ فارسی و راست‌چین برای مقایسهٔ پیشنهادهای پرواز. این برنامه **فروشندهٔ بلیت نیست**؛ قیمت خرید، ظرفیت لحظه‌ای یا پوشش همهٔ پروازها را تضمین نمی‌کند.

## وضعیت واقعی داده‌ها

- جست‌وجوی سایت فقط snapshotهای محلی واقعی Safarmarket را می‌خواند. اگر برای مسیر و تاریخ موردنظر snapshot ندارید، نتیجه خالی نمایش داده می‌شود.
- صفحه‌های وب و API جست‌وجو crawler را اجرا نمی‌کنند؛ جمع‌آوری داده فقط با اجرای صریح CLI یا worker انجام می‌شود.
- نرخ‌های Safarmarket به‌عنوان ریال تفسیر و با نسبت ۱۰ ریال به ۱ تومان تبدیل می‌شوند. snapshot قیمت و ظرفیت را در زمان ثبت نشان می‌دهد و لزوماً هنوز در منبع قابل خرید نیست.
- جدول برنامهٔ آزمایشیِ کد شامل **بیش از ۱٬۱۰۰ برنامهٔ پرواز** و **۱۳۷ مسیر** است؛ این برنامه‌ها دادهٔ جست‌وجو یا موجودی واقعی نیستند. پوشش دادهٔ آزمایشی شامل **۴۷ شهر**، **۲۵ ایرلاین** و مسیرهای **غیرتهرانی** است.

## شروع سریع

نیازمندی‌ها: Node.js و npm. دیتابیس و کلید هوش مصنوعی برای اجرای رابط کاربری لازم نیستند.

```bash
npm ci
npm run dev
```

سپس `http://localhost:3000` را باز کنید. برای دیدن نتایج واقعی باید ابتدا crawler را جداگانه اجرا کنید و snapshot مربوط به مسیر و تاریخ را داشته باشید.

## راهنمای crawler

Crawler دو شیوهٔ اجرا دارد:

1. **اجرای یک‌باره** برای یک منبع، مسیر و تاریخ مشخص.
2. **Worker پیوسته** که هر چرخه مسیرهای تنظیم‌شده را می‌گیرد، snapshot می‌نویسد و قیمت‌های Safarmarket را در تاریخچهٔ PostgreSQL ثبت می‌کند.

Crawler فقط روی میزبانی اجرا شود که مجاز به درخواست از منبع است. از `robots.txt` پیروی می‌کند، برای هر میزبان بین درخواست‌ها مکث دارد، درخواست‌ها را محدود می‌کند و در صورت challenge یا رد دسترسی متوقف می‌شود. هیچ درخواست وب‌سایتی crawler را فعال نمی‌کند.

### ۱. آماده‌سازی محیط

فایل `.env.example` را به `.env` در ریشهٔ پروژه کپی کنید و فقط مقادیر موردنیاز را در فایل محلی قرار دهید:

```bash
cp .env.example .env
```

در PowerShell:

```powershell
Copy-Item .env.example .env
```

`.env` در Git نادیده گرفته می‌شود؛ رمزها، کلیدها و اطلاعات محرمانه را به مخزن اضافه نکنید.

برای Worker پیوسته، PostgreSQL لازم است. دیتابیس را بسازید و سپس کلاینت و schema را آماده کنید:

```bash
npm run db:generate
npm run db:push
```

در `.env` این مقادیر را با مسیرهای واقعی و تأییدشده تنظیم کنید:

```env
CRAWLER_ENABLED=1
CRAWLER_ROUTES=THR-MHD
CRAWLER_SOURCES=safarmarket
CRAWLER_INTERVAL_MINUTES=60
CRAWLER_HORIZON_DAYS=1
CRAWLER_REQUEST_DELAY_MS=10000
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/torob_tickets?schema=public
```

مسیرها جهت‌دار هستند: `THR-MHD` و `MHD-THR` دو ورودی متفاوت‌اند. مسیرهای نمونه را بدون بررسی استفاده نکنید. Worker فقط قالب کدهای IATA را بررسی می‌کند؛ معتبر بودن مسیر را اپراتور باید تأیید کند.

### ۲. اجرای یک جست‌وجوی یک‌باره

یک مسیر و تاریخ را صریح وارد کنید:

```bash
CRAWLER_ENABLED=1 npm run crawl -- --source safarmarket --route THR-MHD --date 2026-11-15
```

در PowerShell، اگر مقادیر را در همان نشست تنظیم می‌کنید:

```powershell
$env:CRAWLER_ENABLED="1"
npm run crawl -- --source safarmarket --route THR-MHD --date 2026-11-15
```

فایل‌های نتیجه در `data/crawl/` ذخیره می‌شوند. مسیر `/crawl` و API سلامت فقط وضعیت و داده‌های محلی را می‌خوانند؛ بازکردن آن‌ها درخواست شبکه‌ای به منبع نمی‌فرستد.

### ۳. اجرای Worker پیوسته

پس از تکمیل تنظیمات محیط و PostgreSQL، اجرا کنید:

```bash
npm run crawl:worker
```

Worker یک چرخه را اجرا می‌کند، سپس به‌اندازهٔ `CRAWLER_INTERVAL_MINUTES` صبر می‌کند و چرخهٔ بعدی را شروع می‌کند. برای توقف، `Ctrl+C` بزنید؛ در Linux از `SIGTERM` نیز پشتیبانی می‌شود.

تنظیمات محدود و اعتبارسنجی می‌شوند:

| متغیر | پیش‌فرض | محدوده / کاربرد |
| --- | --- | --- |
| `CRAWLER_ENABLED` | خاموش | باید دقیقاً `1` باشد تا Worker اجرا شود. |
| `CRAWLER_ROUTES` | بدون پیش‌فرض | فهرست صریح مانند `THR-MHD,MHD-SYZ`. |
| `CRAWLER_SOURCES` | `safarmarket` | `safarmarket`، `basisfly` یا هر دو؛ منابع دیگر در Worker فعال نیستند. |
| `CRAWLER_INTERVAL_MINUTES` | `60` | فاصلهٔ شروع چرخه‌ها، از 60 تا 1440 دقیقه. |
| `CRAWLER_HORIZON_DAYS` | `1` | تعداد روزهای حرکت آینده، از ۱ تا ۱۴. |
| `CRAWLER_REQUEST_DELAY_MS` | `10000` | مکث حداقلی بین درخواست‌های یک میزبان، از 3000 تا 60000 میلی‌ثانیه؛ شامل `robots.txt` هم هست. |

تعداد کل منبع × مسیر × تاریخ در هر چرخه باید در سقف 40 درخواست HTTP، با احتساب `robots.txt` هر میزبان، جا شود. Worker هم‌پوشانی چرخه‌ها ایجاد نمی‌کند. در صورت خطای یک جست‌وجوی مسیر/منبع، خطا ثبت می‌شود و سراغ مورد بعدی می‌رود.

### ۴. فعال‌سازی Basisfly برای سایت بابانوروز

منبع Basisfly به‌صورت پیش‌فرض اجرا نمی‌شود. برای فعال‌سازی، `basisfly` را به `CRAWLER_SOURCES` اضافه کنید و در `.env` خصوصی این دو مقدار را تنظیم کنید:

```env
CRAWLER_SOURCES=safarmarket,basisfly
SECRET_TOROB=مقدار_خصوصی_دریافتی_از_اپراتور
BASISFLY_REQUEST_TEMPLATE={...}
```

`BASISFLY_REQUEST_TEMPLATE` باید **JSON دقیق درخواست مجاز و بدون `SessionId`، cookie، token یا اطلاعات ورود** باشد. کد ساختار API را حدس نمی‌زند. مقدار JSON را در یک خط قرار دهید و متغیرهای وابسته به جست‌وجو را با placeholderهای زیر جایگزین کنید:

- `{{ORIGIN_ID}}` و `{{DESTINATION_ID}}` — شناسه‌های عددی شهرها؛
- `{{DATE}}` — تاریخ حرکت؛
- `{{PASSENGERS}}` — تعداد مسافران؛
- `{{CABIN}}` — اختیاری، اگر در قالب درخواست شما وجود دارد.

نگاشت تأییدشدهٔ نمونه: `MHD → 1211083` و `THR → 1203548`. برای شهرهای دیگر، `BASISFLY_LOCATION_IDS` را با مقادیر تأییدشده تنظیم کنید؛ شناسه‌ها را حدس نزنید.

`SECRET_TOROB` فقط به‌عنوان هدر `SECRET_TOROB` روی POST مربوط به Basisfly فرستاده می‌شود؛ به `robots.txt`، snapshot یا لاگ افزوده نمی‌شود. اگر مقدار secret یا قالب درخواست وجود نداشته باشد، درخواست پیش از اتصال شبکه متوقف می‌شود. مقدار secret را در چت یا Git قرار ندهید.

Basisfly فعلاً snapshot می‌سازد؛ افزودن نرخ‌هایش به تاریخچهٔ قیمت پس از اعتبارسنجی adapter با پاسخ واقعی و پاک‌سازی‌شده انجام می‌شود.

### ۵. مشاهدهٔ وضعیت و لاگ‌ها

Worker دو نوع وضعیت نگه می‌دارد:

- **وضعیت آخرین Worker:** `data/crawl/worker-status.json` و صفحهٔ `/crawl`؛ شامل heartbeat، زمان آخرین چرخه، شمار snapshotها و آخرین خطا.
- **لاگ رویدادها:** `data/crawl/logs/worker.jsonl`؛ هر خط یک JSON مستقل است و زمان، سطح، رویداد، شناسهٔ چرخه، منبع، مسیر، تاریخ، مدت اجرا و شمارش‌ها را نگه می‌دارد. لاگ هم‌زمان روی کنسول نیز چاپ می‌شود.

فایل لاگ با رسیدن به ۵ مگابایت چرخانده می‌شود و حداکثر سه نسخهٔ پشتیبان (`worker.jsonl.1` تا `.3`) نگه داشته می‌شود. اطلاعات محرمانه و مقدار واقعی `SECRET_TOROB` از لاگ حذف می‌شوند.

نمایش زنده در Linux/macOS:

```bash
tail -f data/crawl/logs/worker.jsonl
```

نمایش زنده در PowerShell:

```powershell
Get-Content data/crawl/logs/worker.jsonl -Wait
```

رویدادهای مهم شامل `worker.started`، `cycle.started`، `query.started`، `query.snapshot_written`، `query.failed`، `history.write_failed`، `cycle.finished` و `worker.stopped` هستند. داده‌های `data/crawl/` محلی‌اند و در Git ثبت نمی‌شوند.

برای اجرای دائم روی Linux، فایل `deploy/torob-crawler.service` نمونهٔ systemd است؛ پیش از نصب، مسیر پروژه و کاربر سرویس را اصلاح کنید و فایل محیط را با دسترسی محدود نگه دارید. راهنمای جزئی‌تر crawler در [`docs/CRAWLER.md`](docs/CRAWLER.md) آمده است.

## قابلیت‌های اصلی برنامه

- رابط فارسی و راست‌چین، فرم جست‌وجو و تقویم شمسی.
- یک کارت برای هر پرواز فیزیکی؛ قیمت‌ها و فروشنده‌های همان پرواز برای مقایسه گروه‌بندی می‌شوند.
- فیلتر بر اساس کلاس، توقف، بودجه و ویژگی‌های نرخ؛ مرتب‌سازی قطعی بر اساس قیمت، زمان و مدت.
- صفحهٔ جزئیات پرواز با قیمت، مسیر، فروشنده‌ها و فیلدهای ناشناخته به‌صورت شفاف.
- هوش مصنوعی، در صورت تنظیم کلید، فقط به فهم درخواست و بازنویسی توضیحات کمک می‌کند؛ قیمت، ظرفیت، انتخاب ارزان‌ترین و رتبه‌بندی از داده و قواعد قطعی می‌آیند.
- لوگوهای محلی برای ۲۵ ایرلاین، از جمله مهر و معراج؛ برای کد ناشناخته لوگوی ساختگی نمایش داده نمی‌شود.

## معماری داده

```text
منبع مجاز → CrawlHttpClient → parser منبع → RawOffer → snapshot محلی
                                              └→ adapter معتبر → تاریخچهٔ PostgreSQL
snapshot محلی → adapter جست‌وجو → نرمال‌سازی → ادغام پروازهای یکسان → نتایج
```

`CrawlHttpClient` پیش از درخواست robots را بررسی می‌کند، درخواست‌ها را در هر میزبان صف‌بندی و محدود می‌کند، redirectها را کنترل می‌کند و در صورت challenge از ادامه بازمی‌ایستد. جست‌وجوی وب snapshot محلی را می‌خواند و خودش crawl یا refresh انجام نمی‌دهد.

مبلغ اصلی و واحد ارز در داده نگه داشته می‌شود؛ تبدیل واحد فقط از قواعد منبع یا تبدیل‌گر مشترک پیروی می‌کند. زمانِ بدون منطقهٔ زمانی معلوم، لینک خرید یا ظرفیتِ اعلام‌نشده جعل نمی‌شود.

## راه‌اندازی برنامه و پایگاه داده

برای اجرا و توسعهٔ رابط:

```bash
npm ci
npm run dev
```

برای ساخت و اجرای نسخهٔ production:

```bash
npm run build
npm start
```

برای PostgreSQL محلی، دیتابیس `torob_tickets` را بسازید، `DATABASE_URL` را در `.env` قرار دهید و سپس اجرا کنید:

```bash
npm run db:generate
npm run db:push
```

بدون دیتابیس، رابط و snapshotهای محلی قابل خواندن‌اند؛ Worker پیوسته و تاریخچهٔ ماندگار قیمت به PostgreSQL نیاز دارند. جزئیات اتصال Windows/PostgreSQL در [`docs/CRAWLER.md`](docs/CRAWLER.md) و `prisma.config.ts` آمده است.

## اصول ایمنی و محدودیت‌ها

- درخواست واقعی فقط با opt-in صریح اجرا می‌شود؛ پیش از crawl، مجازبودن دسترسی و قواعد سایت مقصد را بررسی کنید.
- cookie، token، CAPTCHA یا session مرورگر بازپخش نمی‌شود. رد شدن در `robots.txt`، challenge یا تغییر schema به معنی توقف است، نه دورزدن محدودیت.
- ارقام جست‌وجو تنها snapshotهای ثبت‌شده‌اند؛ قیمت زنده، موجودی لحظه‌ای یا موفقیت رزرو را تضمین نمی‌کنند.
- تاریخچه از اولین مشاهدهٔ واقعی شروع می‌شود؛ قیمت‌های گذشته حدس زده یا بازسازی نمی‌شوند.
- خرید بلیت در این پروژه انجام نمی‌شود و لینک خرید از روی حدس تولید نمی‌شود.
- برنامهٔ پرواز آزمایشی برای تست و نمایش ساختار است و به نتایج واقعی تبدیل نمی‌شود.

# ترب بلیت — Torob Tickets

**مقایسهٔ هوشمند قیمت بلیت هواپیما** — یک محصول نمایشی برای چالش مهندسی محصول هوش مصنوعی ترب.

ترب بلیت پیشنهادهای چند ارائه‌دهنده را جمع می‌کند، به یک مدل دادهٔ یکسان تبدیل می‌کند، تکراری‌ها را حذف می‌کند و بر اساس **خواستهٔ واقعی کاربر** (نه فقط ارزان‌ترین قیمت) رتبه‌بندی می‌کند. هوش مصنوعی فقط «فهم درخواست» و «توضیح پیشنهاد» را بر عهده دارد؛ رتبه‌بندی کاملاً قطعی و قابل آزمون است.

> ⚠️ همهٔ قیمت‌ها، پروازها و ارائه‌دهندگان **دادهٔ نمونه** هستند. هیچ اتصالی به API واقعی وجود ندارد و هیچ قیمتی «لحظه‌ای» نیست. این محدودیت در خود محصول هم به کاربر اعلام می‌شود.

```bash

npm test             # vitest — ۹۹ تست واحد/یکپارچه
```

### خط لولهٔ جستجو

```
POST/GET query
   → adapter.search()  ×۴ (موازی، تایم‌اوت ۲.۵s، خطا = فقط همان منبع خراب)
   → adapter.normalize()  (فرمت خودش → FlightOffer؛ دادهٔ نامعتبر کنار گذاشته و گزارش می‌شود)
   → dedupe.groupOffers()  (یک پرواز فیزیکی = یک گروه، چند نرخ)
   → rankOffers()          (امتیاز قطعی + محدودیت‌های سخت)
   → صفحهٔ نتایج / API
```

هیچ‌کدام از مراحل جستجو، dedupe و رتبه‌بندی از هویت ارائه‌دهنده باخبر نیست؛ افزودن منبع جدید (یا **قطار**) فقط یک adapter و یک خط در registry است.

### افزودن ارائه‌دهندهٔ جدید

```ts
export const myAdapter: ProviderAdapter<MyRawOffer> = {
  id: "my-ota",
  name: "آژانس من",
  mode: "demo",
  description: "…",
  quotedCurrency: "IRT",
  async search(query) { /* … */ },
  normalize(raw) { /* از assembleOffer استفاده کنید */ },
};
```

`assembleOffer` مرکزی است: تبدیل ارز، محاسبهٔ مجدد مدت از تایم‌لاین، استخراج تعداد توقف از segmentها، ثبت هشدارها (نبود بار، تبدیل ارز، فرض منطقهٔ زمانی) و ساخت `groupKey`.

### مدل دادهٔ نرمال‌شده

`FlightOffer` شامل: ارائه‌دهنده، ایرلاین، شماره پرواز، مبدأ/مقصد، زمان‌های UTC (+ زمان محلی برای نمایش)، مدت، توقف، segmentها، قیمت اصلی + قیمت تومانی، بار، استرداد، کلاس، لینک، زمان به‌روزرسانی منبع و `warnings[]`.

## چند تصمیم مهم

**۱. اعتماد نکردن به دادهٔ ارائه‌دهنده**
مدت سفر از تایم‌لاین segmentها دوباره حساب می‌شود (فلایتیو عمداً عدد اشتباه می‌دهد)، تعداد توقف از تعداد segmentها (نه از رشته‌های `"direct"`/`"۲ توقف"`)، و قیمت ریالی/یورویی با جدول نرخ نمونه به تومان تبدیل و با هشدار `price-converted` علامت می‌خورد.

**۲. دادهٔ نامشخص هرگز حدس زده نمی‌شود**
اگر ارائه‌دهنده بار یا استرداد را اعلام نکند، مقدار `null` می‌ماند، در UI «نامشخص» نمایش داده می‌شود و هوش مصنوعی اجازهٔ ادعا درباره‌اش را ندارد.

**۳. حذف تکراری محافظه‌کارانه**
کلید یکسان = ایرلاین + شمارهٔ پرواز یکسان‌سازی‌شده + روز حرکت در مبدأ + مسیر. پرواز بدون شماره فقط اگر اختلاف زمان حرکتش با یک پرواز شماره‌دار کمتر از ۳۰ دقیقه باشد به آن می‌چسبد. تست‌ها موارد منفی (قیمت مشابه، پرواز متفاوت) را پوشش می‌دهند.

**۴. رتبه‌بندی قطعی، هوش مصنوعی فقط توضیح‌دهنده**
`score = Σ wᵢ · sᵢ` با `sᵢ ∈ [0,1]`؛ زیرامتیاز قیمت/مدت نسبتی است (`بهترین / مقدار`) تا یک پرواز بیزینس گران، کل بازه را فشرده نکند. وزن‌ها از intent می‌آیند و نرمال می‌شوند. محدودیت‌های سخت (توقف، بار، استرداد، بودجه، بازهٔ ساعت) گزینه را حذف نمی‌کنند؛ در بخش «خارج از ترجیحات شما» با دلیل نمایش داده می‌شوند.

**۵. هوش مصنوعی قابل حذف**
بدون `OPENAI_API_KEY`: پارسر قطعی فارسی/انگلیسی intent را می‌سازد و توضیح‌ها از قالب‌های قطعی می‌آیند. با کلید: مدل فقط می‌تواند بازنویسی کند؛ خروجی باید با Zod معتبر شود و از `checkGrounding` بگذرد (هر عددی که در داده نیست، هر ادعا دربارهٔ فیلد ناشناخته، هر شماره پرواز دیگر → رد و استفاده از قالب). کلید فقط سمت سرور است.

**۶. ماندگاری اختیاری (Postgres محلی، بدون داکر)**
اجرای دمو کاملاً در حافظه است و به دیتابیس نیاز ندارد. اگر `DATABASE_URL` ست شده باشد، هر جستجو به‌صورت best-effort ثبت می‌شود: snapshot پیشنهادهای نرمال‌شده + لاگ جستجو (intent، تعداد نتایج، بهترین پیشنهاد). خطای دیتابیس هیچ‌وقت صفحه را نمی‌شکند و پیام یک‌بار در کنسول لاگ می‌شود.

Postgres خودِ ویندوز کافی است — جزئیات در بخش «اتصال به Postgres روی ویندوز».

**۷. زمان و تاریخ**
همهٔ زمان‌ها به UTC ذخیره می‌شوند؛ زمان محلی هر فرودگاه با `Intl` محاسبه می‌شود (بدون جدول offset دستی، با احتساب DST). تاریخ‌ها در UI شمسی و با ارقام فارسی‌اند؛ تقویم شمسی با الگوریتم حسابی نوشته و با تاریخ‌های مرجع تست شده است (۱ فروردین = ۲۱ مارس).

## اتصال به Postgres روی ویندوز (بدون داکر)

دیتابیس خودتان کافی است؛ هیچ container‌ای لازم نیست.

### ۱) ساخت دیتابیس

با pgAdmin یا `psql`:

```sql
CREATE DATABASE torob_tickets;
```

### ۲) ست کردن `DATABASE_URL`

`DATABASE_URL` باید شامل **نام کاربری، رمز، هاست، پورت و نام دیتابیس** باشد. اگر رمزتان کاراکترهای خاص دارد (`@ : / ? # %`) آن را URL-encode کنید (مثلاً `@` → `%40`).

**PowerShell (فقط برای همان پنجرهٔ ترمینال):**
```powershell
$env:DATABASE_URL="postgresql://postgres:MyPass@localhost:5432/torob_tickets?schema=public"
```

**CMD:**
```cmd
set DATABASE_URL=postgresql://postgres:MyPass@localhost:5432/torob_tickets?schema=public
```

**یا دائمی‌تر:** یک فایل `.env` در ریشهٔ پروژه بسازید (در `.gitignore` هست، کامیت نمی‌شود):
```
DATABASE_URL="postgresql://postgres:MyPass@localhost:5432/torob_tickets?schema=public"
```

> اگر پورت پیش‌فرض را عوض کرده‌اید (مثلاً نصب با EDB معمولاً 5432 است)، همان پورت را در URL بگذارید. سرویس `postgresql-x64-16` باید در `services.msc` در حال اجرا باشد.

### ۳) ساخت جدول‌ها و دادهٔ نمونه

```powershell
npm run db:generate
npm run db:push       # ساخت جدول‌ها از schema.prisma
npm run db:seed       # پر کردن با خروجی واقعی خط لولهٔ جستجو
npm run db:studio     # (اختیاری) مرور داده‌ها در مرورگر
```

### ۴) اجرا

```powershell
npm run dev
```

از این به بعد هر جستجو در `search_logs` و `offer_snapshots` ثبت می‌شود. برای بررسی سریع:

```sql
SELECT origin_code, destination_code, result_count, source, created_at
FROM search_logs ORDER BY created_at DESC LIMIT 10;
```

### اگر خطا گرفتید

| خطا | علت | راه‌حل |
|---|---|---|
| `Can't reach database server` | سرویس Postgres خاموش است یا پورت/هاست غلط است | سرویس را در `services.msc` روشن کنید، `localhost:5432` را چک کنید |
| `password authentication failed` | رمز یا نام کاربری غلط | با pgAdmin همان رمز را تست کنید؛ کاراکترهای خاص را URL-encode کنید |
| `database "torob_tickets" does not exist` | دیتابیس ساخته نشده | `CREATE DATABASE torob_tickets;` |
| `@prisma/client did not initialize yet` | `prisma generate` اجرا نشده | `npm run db:generate` |
| صفحه با خطای دیتابیس بالا نمی‌آید | نباید رخ دهد — نوشتن best-effort است | `DATABASE_URL` را بردارید؛ اپ بدون دیتابیس هم کامل کار می‌کند |

> **نکته:** بدون `DATABASE_URL` هیچ‌چیز خراب نمی‌شود؛ دمو کاملاً در حافظه اجرا می‌شود. ماندگاری یک قابلیت اضافه است، نه پیش‌نیاز.

## محدودیت‌های شناخته‌شده

- **دادهٔ نمونه**: افزایش قیمت با نزدیک‌شدن تاریخ، جدول پرواز هفتگی، نرخ ارز ثابت — همه ساختگی و مستند.
- **پرواز رفت‌وبرگشت**: فرم نوع سفر و تاریخ برگشت را می‌پذیرد، اما نتایج فعلاً فقط پای رفت را نشان می‌دهند.
- **بلیت واقعی**: لینک‌ها به دامنهٔ نمونه می‌روند و خرید انجام نمی‌شود.
- **قطار**: مدل دامنه و لایهٔ ارائه‌دهنده، مستقل از وسیلهٔ سفر طراحی شده‌اند اما پیاده‌سازی نشده‌اند.
- **Playwright**: اجرای خودکار نتیجه به نصب مرورگر نیاز دارد؛ در محیط محدود، پوشش همان جریان با `journey.dom.test.tsx` انجام می‌شود.
- **Prisma**: تولید کلاینت به دسترسی شبکه نیاز دارد؛ در نبود آن، لایهٔ ماندگاری غیرفعال می‌ماند و دمو اثری نمی‌بیند.
